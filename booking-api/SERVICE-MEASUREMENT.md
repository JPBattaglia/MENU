# Service measurement — October 16, 2026

Run `service-funnel-report.sql` read-only in the existing D1 database console. There is no public analytics page and no new analytics account. It reports the past 30 days by first-touch source, medium, campaign, and service. Counts are distinct sessions per service; someone exploring two services appears under both. A received inquiry is a successful browser API receipt, not a qualified lead, approved quote, appointment, or sale.

The existing `/api/funnel-event` handler accepts `CTA_CLICK` and `OFFER_VIEW` and serializes the event's metadata. The browser now sends only these allowlisted `metadata.service` values: `online_menu_qr`, `conversion_fix`, `google_visibility`, `accessibility_upgrade`, `website`, `app`, `other`. Aliases in public service links are normalized. Website/app/other never create invented backend offer IDs; the four existing paid offer IDs remain unchanged.

Service pages record an offer view. Archive case pages record `case_study_view`; the illustrative app demo records `demo_view`. The existing interactive menu records `sample_menu_view`. Website/app inquiry links record `quote_started`. Form code records `inquiry_attempt` and `inquiry_received` with the service slug, plus `quote_started`/`quote_received` for website or app inquiries. Quote completion is recorded only after a successful inquiry receipt. These are stages of the existing `CTA_CLICK` event; the browser never claims a purchase. Live paid outcomes in the report come from existing server checkout records joined to actual paid orders and live order items.

Include `funnel.js?v=20261016-service-measurement` once on marketing, service, case, demo, contact, and checkout-success pages. About and the accessibility statement should receive the script too. The implementation recognizes clean and `.html` forms of approved paths. Paths outside the fixed list are recorded only as `/other`. It never collects query strings, full referrer URLs, contact names/emails, messages, filenames, or document contents. Only approved campaign tokens, referrer hostname, and the existing random session ID are retained. DNT, GPC, and `?mm_measurement=off` disable measurement. `?mm_measurement=test` marks a session as an internal test; the report excludes it.

New metadata is not backfilled into historical events. Use the existing `funnel-report.sql` for the broader historical visit-to-order report; the service report gives a breakdown once the new service signals have been collected. A session without a service signal and without an attributed supported-service checkout is absent from the service report. Website/app quotes have no paid outcome in this report unless a future server-supported order model explicitly attributes those services. Do not interpret a zero in those paid columns as a failed quote.

Weekly review: compare interested sessions, received inquiries, quote receipts, and paid orders by service and source. Inspect actual inquiries privately before deciding which are qualified. Small samples show observed counts, not evidence of a causal lift. No page-speed scores or real-user performance metrics are claimed here; performance needs a separately recorded measurement with its device and test conditions.

Validation: frontend tests cover service normalization, quote completions, duplicate suppression, paid-ID preservation, approved paths, opt-outs, and isolation from network failures. Run `python3 booking-api/service-report.test.py` for SQL fixtures covering duplicate events/items, internal tests, sandbox orders, and distinct paid-session counts. Do not submit a real inquiry or payment solely to verify instrumentation.
